# Review: Issue #241 — Doctor's Note Utility

Reviewed with: Codex

Issue: https://github.com/dave0875/HealthDelta/issues/241

## Summary
- Replaces the old doctor-note key/value dump with a deterministic two-part note: human-facing `Summary` first, machine-readable `Facts` second.
- Keeps ORIN-compatible fact lines such as `event_time_range`, `sources.*`, and `signals.top_observations`.
- Tightens the Ollama refinement prompt so it prioritizes meaningful findings and limitations over operational row counts.

## Risks / Gaps
- [severity: low] The note is still bounded by available structured signals. Sparse datasets will remain limited, but they should now communicate that clearly without leading with raw counts.
- [severity: low] Some observation labels remain code-like when no friendlier mapping exists; that is preferable to inventing clinical meaning.

## Privacy / Share-safe checks
- No names, DOB, canonical IDs, or free-text clinical narratives are emitted.
- Row counts and structured signal labels remain share-safe.
- Human-facing summary text is derived solely from deterministic aggregates.

## Determinism checks
- The note remains byte-stable for the same DB.
- `generated_at` is still derived from the maximum event time in the DB.
- Summary bullets are deterministic because they depend only on ordered aggregates and fixed wording.
