# Review: Issue #259 Follow-up — Nested ZIP Member Exclusion

Reviewed with: Codex

Issue: https://github.com/dave0875/HealthDelta/issues/259

## Summary
- Fixed the refresh extractor so `--exclude-member export_cda.xml` matches both an exact ZIP member path and a nested member basename such as `apple_health_export/export_cda.xml`.
- Added a regression test for the nested-member exclusion behavior.
- Updated the automation runbook to document the basename-matching behavior.

## Findings
- [severity: medium] The live failure on `GORF` was caused by exact-path exclusion only. The service passed `--exclude-member export_cda.xml`, but the archive member path was nested under `apple_health_export/`, so the malformed CDA file still reached `healthdelta export profile`.

## Risks / Gaps
- [severity: low] The live rerun can still fail for a different export-quality or environment issue after the CDA workaround is applied; success requires a post-push rerun on `GORF`.
