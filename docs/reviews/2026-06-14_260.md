# Review: Issue #260 — Streaming Repair for Malformed Large CDA

Reviewed with: Codex

Issue: https://github.com/dave0875/HealthDelta/issues/260

## Summary
- Added a streaming CDA repair layer that can recover from a premature `</ClinicalDocument>` followed by additional content and a missing final root close.
- Added explicit truncation detection that fails with a resubmission message naming `dave0875@gmail.com`.
- Routed profile, de-id, and NDJSON export through repaired CDA input instead of requiring CDA exclusion.

## Findings
- [severity: medium] The prior pipeline treated a recoverable Apple export defect as fatal and forced operators to exclude CDA, losing clinically relevant derived rows and section coverage.
- [severity: medium] `deid.py` previously read multi-GB XML files into memory, which is not viable for the observed export sizes.
- [severity: low] The existing `healthdelta/ndjson_export.py` file is root-owned in this environment, so the refactor uses a wrapper module to inject repaired CDA parsing without rewriting that file directly.

## Risks / Gaps
- [severity: low] CDA rows are still accumulated into in-memory row lists before NDJSON write/sort, so extremely large CDA-derived row counts may need a follow-up streaming/chunked export refactor even after malformed-file repair is fixed.
